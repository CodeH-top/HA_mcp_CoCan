# MQTT 能力与独立分支

**当前版本 0.4.1b12**：固件更新功能按用户要求撤下，历史 b1–b6 的 OTA 说明仅作开发记录，不代表当前可用功能。更新使用官方 App；卡片作为概览组件提供，见 README。

MQTT 实现位于 `mqtt` 分支，主线仍用官方 MCP。日常轮询不修改设备 Broker；管理员在 Broker 选择或快捷切换页面二次确认后，才同步切换设备端，详见文末 b12。下文带旧版本号的章节保留当时的能力与验证记录。MQTT 需要 HA 的 MQTT 集成和可访问的自建 Broker；设备切换接入方式可能影响官方 App 的部分云功能，请先阅读官方接入说明。

## 公开协议能做到什么

| 功能 | MCP | MQTT 公开协议 |
| --- | --- | --- |
| 基础遥测、端口输出控制 | 支持 | 支持 |
| 当前充电策略读取 | 不支持 | 支持 |
| 整机电源、重启 | 不支持 | 支持，区别于物理切断电源 |
| 屏幕、端口配置、PD、Wi-Fi 管理 | 部分 | 多类命令，随固件版本变化 |
| OTA 发起与升级状态 | 不支持 | START_OTA 与升级遥测 |
| 自动发现最新固件 | 不支持 | 未见公开的固件版本目录或查询命令 |
| 账号、订阅、素材授权、云统计 | 不支持 | 无法单靠设备 MQTT 复刻 |

因此不能声称完整复刻小程序。OTA 执行命令不等于更新检测；没有可信版本目录时必须显示未知，不能显示“已是最新”。不执行猜测版本的自动 OTA。

## 协议注意事项

官方请求 topic 为 `device/<psn>/enduser/request/<十进制命令号>`，响应为 `.../response/<十进制命令号>`，载荷为 protobuf。命令号与 CommandRequest 的 oneof 字段号不同。响应必须匹配设备、命令、请求 ID 与成功状态；不能使用 retained 响应完成新请求。

官网 schema 与开源固件的屏幕配置命令号、字段号有差异，不能盲目把不同版本混用。MCP 地址中的访问密钥不用于 MQTT 数据包，Broker 认证、TLS 和 ACL 在 HA MQTT 集成配置。

## 当前分支的实际实现（0.4.1b2）

此版本是实验分支，不是完整小程序替代。添加集成时选择“自建 MQTT”，填写 PSN；不填写 MCP 地址。配置流程先 GET_DEVICE_INFO 核验 topic 对应的真实 PSN，不通过则不创建条目。Broker 地址、账号、TLS、证书均沿用 HA MQTT 集成，不在组件中另存一套。

已实现并经官网 protobuf 生成器交叉验证：

- MQTT 二进制请求/响应，topic 使用十进制命令号；逐请求随机起点递增 ID、设备/命令/ID 关联、成功状态校验、8 秒超时、QoS 1、请求不保留、拒绝 retained 响应、卸载退订。
- 五口电压、电流、计算功率、快充协议与充电位图；可用实时流补充连接状态和功率预算，数据超过 30 秒不使用。原始累计电量不冒充 mWh。
- 端口开关、整机电源、设备重启、当前策略读取与四种公开策略设置、五口临时功率分配；整机关机后仍可轮询电源状态并开机。
- 内置卡片复用上述实体，增加整机电源/重启入口；单口控制按 A/C1/C2/C3/C4 映射为 MQTT 的 0/1/2/3/4。
- 固件更新实体：与管理员配置的目标组合比较，默认只检测，OTA 必须另行开启；拒绝型号不匹配、降级、未配置目标及重复升级。监听升级成功/失败遥测，请求 ACK 不视为升级完成。
- MQTT 新设备实体以 PSN 隔离 unique ID；不会改写既有 MCP 实体身份。同一 PSN 不创建两个配置条目；在配置选项中切换连接方式，保留两套参数和既有实体身份。

尚未实现为 HA 控件：屏幕新/旧协议配置、PD 详情/抓包、协议开关/PDO/线损补偿、Wi-Fi 管理、静态分配表、计划任务、动画素材。原生 MQTT 协议具备其中部分能力，但本分支不会给未接通或未核实的功能生成可操作控件。屏幕命令存在同号异义，尚未提供自动识别兼容层。

### 固件目标配置

在 MQTT 配置条目的“配置”中填写（以下版本仅演示格式，**不可直接用于设备升级**）：

```json
{"model":"与你设备 GET_DEVICE_INFO 返回完全一致的型号","esp32":"2.2.1","sw3566":"1.0.0","fpga":"0.2.19"}
```

必须从厂商核实整套可用的版本与设备兼容性。`model` 严格匹配设备返回值；版本均为 `major.minor.patch`，不传 force。该配置不是下载地址，也不提供厂商固件目录；升级所需文件仍由设备固件按其自身机制下载。未填目标时更新实体为未知。配置目标不同会显示存在更新，执行前还会拒绝组件降级。

### 验证边界

已在临时环境编译官网三份 schema，用独立生成的 protobuf 编解码交叉验证所有实现命令字段及模拟设备交互，覆盖错误状态、错误 ID、retained、端口编号、预算、关机后恢复、OTA 型号/开关/结果、订阅清理，并做构建和卡片 DOM 验证。生成文件仅用于临时验证，没有进入源码和发布包。

没有切换用户真实设备 Broker，没有实机验证 MQTT 固件 profile，没有执行实际开关机、断开充电或 OTA。官网协议与不同固件的兼容性仍需要在准备好的测试设备上验收；不能将这些模拟测试解释为实机通过。


## 连接方式切换与局域网地址（0.4.1b2）

设备 IPv4/主机名可以在添加设备、当前连接参数、连接方式切换表单中手动填写或修改，不写死为某台设备的地址。已在 App 2.2.0 / FPGA 0.2.19 的真实 CP-02S 上核对首页 PSN 与 `/metrics.json`；HA 可访问而客户端电脑直连不通时，遥测仍以 HA 到设备的网络为准。

HA 接入方式支持往返切换：**集成 → 配置 → 切换官方云 / 自建 MQTT**。官方模式是“设备使用官方 MQTT，HA 通过官方 MCP 接入”；自建模式沿用 HA MQTT 集成，不尝试拿设备私有证书让 HA 直连厂商 Broker。

1. 在设备本地页面完成设备 Broker 切换，使其连接到目标服务器。卡片提供“设备本地配置页”链接；打开此页面还需要浏览器能访问设备网段。
2. 在 HA 连接方式表单选择官方云或自建 MQTT。保存前只读核验目标 PSN；失败保持现有配置，并清理临时 MQTT 订阅。
3. 返回官方云时使用保存的 MCP 地址，也允许手动更新；整个过程不删除配置条目、设备或注册表。共享实体沿用原 ID，自建模式不支持的旧实体保留注册记录，但从卡片操作列表隐藏；回到官方模式后恢复。

设备首页实际列出了 `/setbrokerz`、`/destroymqttz`、`/startmqttz`，且报告当前 Broker 配置；但这些入口有写入副作用，公开仓库缺少对应处理器，厂商前端资源本次无法获取以核对完整参数和恢复语义。**本版没有调用它们，不把 HA 接入方式切换冒充设备 Broker 一键切换。** 设备 Broker 自动写入须等契约核实后再接入，不能猜测空地址就代表恢复官方。

MQTT 模式同样支持 PSN 核验的 LAN 读取，优先使用本地基础数据；MQTT 断连时保留本地遥测并禁用控制，不沿用上一轮电源/充电状态。连接设置入口仍可使用，便于恢复。

本轮通过临时测试覆盖新旧条目的 MCP/MQTT 往返、共享实体身份、MCP 参数保留、错误设备/断连不保存、LAN 回退及禁用控制；设备 Broker 没有实际切换，MQTT 仍未做真实设备验收。


## 0.4.1b3：严格 MQTT 模式

用户选择 MQTT 后，所有本组件已实现的设备读取、控制和 OTA 请求均只走 HA MQTT 集成；不读取 `/metrics.json`，不回退云端 MCP。Broker 断连或设备响应失败则显示离线并拒绝控制，不继续显示 HTTP 读数。先前 b2 的 MQTT+LAN 回退行为被此规则取代。

手动设备 IP 仅作为打开设备本地配置网页的地址，自动轮询不使用它。切回官方云模式属于管理员显式配置操作，才会测试/使用 MCP。尚未实现的功能依然不提供控制，不会为了补齐界面偷偷使用云端接口。

## 0.4.1b4：按设备 Broker 选择接入方式

配置 → 切换官方云 / 自建 MQTT → “根据设备 Broker 检测”：保存时仅一次性读取经 PSN 核验的首页 Broker。当前已核实的官方主机 `iot-broker.ifanrusercontent.com` 选择 MCP；自建 Broker 必须与 HA MQTT 集成的协议、端口、主机（或解析地址）相匹配，再以只读 MQTT 身份探测确认设备。无法匹配就不保存，不把任意相似厂商域名当官方。

切换表单直接读取 HA MQTT 集成配置，显示不含凭据的 Broker URI；本机 Mosquitto 的内部地址 `core-mosquitto` 根据通往设备网段的 HA 网卡映射为局域网 IP。账号密码/客户端证书仍由 HA MQTT 集成管理，本组件不复制到配置或前端。设备自身连 Broker 需要的认证仍要在设备端配置，不能把 HA 内部自动生成凭据当作设备通用凭据。

这不是后台持续 HTTP 扫描：Broker 检测只在管理员保存连接方式表单时运行。正常 MQTT 模式所有设备轮询和控制仍严格仅走 MQTT；设备 Broker 改变后重新运行检测即可。同一配置条目共享实体保持原 ID，未实现的协议特有实体保持注册记录但不显示为可操作。

设备端 Broker 自动写入仍未实现，原因和恢复边界见前文；本功能读取设备已选择的 Broker 并切换 HA 协议，不声称已修改设备服务器。


## 0.4.1b5：只配置 Broker 地址

连接页仅保留“Broker 地址”，删除协议选择和“根据 Broker 检测”选项及长段落说明。首次默认带出 HA MQTT Broker，后续显示已保存地址，可手动输入自定义地址。保存时根据地址主机自动判断：已核实的官方主机用 MCP，其余全部用 MQTT，不因连接失败改走 MCP。

自定义 Broker 的认证与连接仍通过 HA MQTT 集成管理，因此本版要求该地址与 HA MQTT 中的服务器一致；不同地址应先在 HA MQTT 集成中配置。组件不自动改全局 HA MQTT 设置，不复制密码。Broker 地址只表示本集成目标连接，仍不代写设备端 Broker。

原设备 IP、官方 MCP 参数移至“当前连接参数”维护，无需在 Broker 页反复填写。共享实体 ID 和两套参数继续保留。历史 b4 的下拉选项、检测按钮与描述均已由本节替代。

## 0.4.1b6：恢复官方服务器与固件界面

“配置 → 恢复官方 Broker”会预填保留的官方地址 `mqtts://iot-broker.ifanrusercontent.com:8883`，仍须保存并验证同一 PSN 的 MCP 连接。独立保存 `official_broker_url`，切到 HA Broker 不覆盖官方地址或 MCP 参数。此操作只修改 HA 的接入配置；设备自身应先通过本地配置页切回官方服务器，不能把 HA 保存成功视作设备 Broker 已修改。

MQTT 卡片新增固件面板：三芯片当前版本、管理员目标版本、刷新设备版本、原生更新详情、安装目标版本，以及升级中、失败和超时反馈。默认关闭 OTA，启用后仍需明确确认安装；版本/型号校验和禁止降级在后端执行。升级遥测须匹配本次请求的三芯片目标版本；成功遥测显示“设备报告成功”，需刷新设备版本进一步核对。未匹配的报告和请求 ACK 不当作升级成功。

### 官方固件接口调查（2026-11-04）

- [官方 MQTT START_OTA](https://thecandysign.com/cocan/zh/mqtt/reference/) 只接受 ESP32、SW3566、FPGA 的目标版本和 force；没有固件文件上传、下载 URL 或“最新版本查询”参数。本组件只通过 MQTT 发起，不改变设备下载来源。
- [官方全模 OTA 介绍](https://thecandysign.com/cocan/zh/ota/) 介绍能力，没有机器可读的型号/硬件修订兼容目录、校验和或下载 API。
- [公开固件配置](https://github.com/ifanrx/IonBridge/blob/main/components/firmware/Kconfig.projbuild) 的 FIRMWARE_DOWNLOAD_ENDPOINT 和 FIRMWARE_CHECKSUM_DOWNLOAD_ENDPOINT 默认空；[升级实现](https://github.com/ifanrx/IonBridge/blob/main/components/firmware/upgrade.cpp) 的下载部分为占位实现，不能据此推导生产接口。
- [仓库 version.json](https://github.com/ifanrx/IonBridge/blob/main/version.json) 的应用版本 0.9.11 早于已实读设备的 2.2.0，且不是生产固件发布目录。不能用 GitHub 提交、营销页面或单颗芯片版本拼出可刷写的“最新组合”。

因此本版没有宣称接通官方最新固件查询，也没有实现 HA 下载后上传设备。界面明确标记检测未接通，缺目标显示“未配置”，不显示“已是最新”。接通自动检测还需要厂商公开的查询契约（认证、型号/硬件修订/发布渠道、整套版本和下载校验）；本轮不猜测私有 API，也没有实际执行 OTA。

## 0.4.1b9：以 MCP 清单逐项补齐数据与控制

MQTT 恢复 152 个共享实体身份，并增加 32 个 MQTT 实体，共 184 个；逐项状态见 [实体对照表](MQTT_ENTITY_PARITY.md)。其中 136 个共享字段已接入来源或条件性映射；16 个因协议缺少温度字段、原始电量单位不明或没有硬件额定预算而保持未知。保留未知实体是为切换身份一致，不代表已完整实现。

- 新接入 PSN/FPGA/Wi-Fi SSID、BSSID、RSSI（protobuf sint32）、信道和协议；新增应用/协议芯片/协议库版本传感器。
- 五口 PD 按 0–4 请求再转换为 HA 1–5。接入 E-Marker、PD 修订、PDO、10mV/10mA 工作值、线缆额定电压与 USB 速度、主动线/双角色、电池容量与百分比、PDP。只查询充电中的 PD 口；未知/失败不冒充零值，不让单口失败拖垮基础遥测。
- 按 CoCanBar MIT 厂商表与 USB 规格补充品牌及线缆规格，原始 VID/PID 独立保留。显示“Apple 设备（型号未识别）”或 VID/PID，不把品牌猜成具体产品型号；无 E-Marker 不显示虚构的线缆规格。
- 温控读取来自设备/配置推送，设置用 0x5B；亮度使用各版本一致的 0x72 只读/0x70 写入，HA 四档预设 0/25/50/100%，并非 MCP 私有分档原样复刻。
- 屏幕模式、待机动画和报时从公开推送读取，整套修改用官网 0x7F/tag91 的 DisplayConfig。须有30秒内配置并包含报时值，保留旋转/亮度/动画时长；ACK后等设备新回报，不填乐观状态。没有完整配置就拒绝写入。公开 IDLE_RIPPLE 不等于 MCP“落花”，不映射为落花。旧固件可能不支持0x7F，失败不尝试其它写入编号。
- 0x7D 在官网与旧固件中有 GET/SET 同号差异，因此不探测0x7D来读取，避免产生写入。屏幕完整状态依赖0x81设备推送/0x80配置报告；缺字段时仅亮度/模式可通过两个确定的只读命令补充。
- 新增当前/剩余功率预算、五口原始session_charge计数；不将动态预算当硬件最大功率，不把原始计数换算mWh。boot数据只选取product_family/device_model，绝不保存/暴露内含的MCP token。

推送有效期30秒，断连清缓存；PD只使用本轮推送或有界2秒/口请求。主轮询总上限60秒；MQTT断连显示离线并禁写，不回退MCP/HTTP。新增控制仅模拟验证，未做真实断供、设备重启或Broker切换；固件更新保持删除状态。UI本轮不改。


## 0.4.1b11：恢复官方时同步恢复设备 Broker

此前“恢复官方”只预填 HA 表单，设备仍连接自建 Broker，官方 MCP 因设备离线而失败。现在通过该菜单保存官方地址时，先验证已配置局域网地址的设备 PSN，以及首页宣告的恢复接口。对非官方 Broker，以空文本 POST /setbrokerz 清除自定义覆盖，再依次 GET /destroymqttz、/startmqttz 重建 MQTT 客户端；保留厂商保护配置/证书，不重启整机或断开供电。随后重新验证设备实际 Broker 为官方端点，并有界重试官方 MCP 身份读取，通过后才保存 HA 的 MCP 模式。

局域网访问限定私网 IPv4，固定解析地址、禁重定向、限制响应体；身份或接口不匹配时不写入。设备已用官方 Broker 时不重复重建客户端。设备恢复失败与云服务未就绪分别返回明确中英文错误，不回显包含凭据的 Broker URI；云服务未就绪时设备可能已经恢复官方，HA 设置尚未保存，稍后通过同一入口重试即可。普通 Broker 表单只校验 HA 接入，后台 MQTT 轮询仍不调用 HTTP/MCP。切到自建 Broker 的设备端账号配置继续由设备页面完成。


## 0.4.1b12：统一 Broker 菜单、快捷切换与确认

配置首页为“当前连接参数 / MQTT Broker / 快捷切换 Broker”；移除独立“恢复官方”菜单。“MQTT Broker”内为官方、自定义两项，自定义地址默认来自 HA MQTT 集成。快捷切换根据已核对 PSN 的设备实际 Broker 准备相反方向，不以可能过期的 HA 模式猜测。

所有入口均只先读取设备、准备目标，统一进入二次确认页，显示当前与目标的无凭据地址和 MCP/MQTT 协议。确认默认未勾选；打开/选择/关闭/未确认提交不写设备或 HA 配置。确认提交后重新核对设备当前端点；与预览不同则更新预览并要求再次确认。设备写入前也验证同一来源，防止对话框停留后误切。旧对话框路由同样转入确认，不能绕过。

自定义目标须与 HA MQTT 集成匹配；确认后临时取该集成的账号密码，组装设备端 URI，通过固定私网 IP、同 PSN 和明确接口核验的 HTTP 请求写入。认证不存入本集成 entry、表单、前端、日志或协调器。官方方向清除自定义覆盖，保留厂商证书。两个方向均只重建 MQTT 客户端，重新检查设备选定的端点与目标服务 PSN，通过后保存 HA 模式；不重启整机、不断供。服务尚未就绪时设备可能已切到目标，HA 设置未保存，页面显示实际来源并提示重试。

共享152个实体身份不变，MQTT额外32个切回官方后不可用、再切回MQTT复用。正常MQTT轮询/控制仍仅走MQTT；此版本的HTTP写入仅在管理员明确二次确认切换时执行。界面确认链与设备端双向写入经临时回归验证，未替用户勾选实机切换确认。
